# A · Glossary

One-line definitions for terms used in the handbook. The first chapter after each entry is the one that covers the term in depth; any others use it or apply it. Use the glossary for quick revision: cover the definition and say it out loud, then add the one number or formula that goes with it (Appendices B and C have them).

## A–C

- **A/B test**: randomised experiment comparing variants on live traffic to measure causal impact. (Ch 2, 47)
- **Activation function**: non-linearity applied after a linear layer (ReLU, GELU, SiLU). (Ch 5)
- **Activation patching**: replace one component's activation in a corrupted run with its clean-run value to test whether it carries the information behind a behaviour. (Ch 26)
- **AdamW**: Adam optimiser with weight decay decoupled from the gradient update; the default for transformers. (Ch 7, 6)
- **Agent**: an LLM in a loop that chooses actions (tool calls) based on observations until a goal is met. (Ch 33)
- **Alignment faking**: a model strategically complying with training it disagrees with to avoid being modified, observed in constructed settings. (Ch 27)
- **ALS**: alternating least squares, a matrix-factorisation method for implicit-feedback recommenders. (Ch 43)
- **ANN (approximate nearest neighbour)**: fast vector search trading a little recall for speed (HNSW, IVF, PQ). (Ch 30, 29)
- **Arithmetic intensity / roofline**: FLOPs performed per byte moved from memory; below the hardware's ratio of peak FLOP/s to bandwidth (about 300 for an H100 in bf16) an operation is memory-bound, above it compute-bound. (Ch 21, 10)
- **Attention**: weighted sum of value vectors, with weights from query-key similarity. (Ch 10, 8)
- **Attention sink**: a token (often the first) that receives large attention regardless of content; streaming inference must keep it. (Ch 10)
- **AUC (ROC-AUC)**: probability a random positive is scored above a random negative. (Ch 4)
- **Autograd**: automatic differentiation that records operations and back-propagates gradients. (Ch 6)
- **Auxiliary-loss-free balancing**: MoE load balancing by adjusting per-expert selection biases instead of adding a loss. (Ch 11)
- **AWQ / GPTQ**: post-training 4-bit weight quantisation methods for LLMs. (Ch 21)
- **Backpropagation**: computing gradients layer by layer with the chain rule. (Ch 5)
- **Bandit**: sequential decision method balancing exploration and exploitation (ε-greedy, UCB, Thompson sampling). (Ch 43, 18)
- **Batch normalisation / layer normalisation**: normalising activations across the batch / across features of one example. (Ch 5, 10)
- **Beam search**: decoding that keeps the B most probable partial sequences. (Ch 21)
- **Bi-encoder / cross-encoder**: encode query and document separately (fast, indexable) / together (accurate, slow). (Ch 30, 29)
- **Bias–variance trade-off**: error from wrong assumptions vs error from sensitivity to the training sample. (Ch 3)
- **Bits per byte**: loss normalised by text length in bytes; compares models with different tokenizers. (Ch 23)
- **BM25**: classic lexical ranking function using term frequency, inverse document frequency and length normalisation. (Ch 30)
- **Bootstrap**: resampling the independent unit (users, queries, questions) with replacement to estimate a confidence interval. (Ch 4, 2)
- **BPE (byte-pair encoding)**: subword tokeniser built by repeatedly merging the most frequent adjacent pair. (Ch 9)
- **Bradley–Terry model**: P(a preferred over b) = σ(r_a − r_b); the likelihood behind reward models, DPO and Elo-style leaderboards. (Ch 18, 23)
- **Budget forcing**: controlling a reasoning model's thinking length at inference by ending or extending its thinking. (Ch 19)
- **Calibration**: predicted probabilities match observed frequencies. (Ch 4)
- **Canary release**: sending a small share of traffic to a new version with automatic rollback rules. (Ch 47)
- **Chain-of-thought**: prompting or training the model to reason step by step before answering. (Ch 22, 19)
- **Chain-of-thought monitoring**: using a model (or people) to read reasoning traces for signs of misbehaviour such as reward hacking. (Ch 27)
- **Chinchilla scaling**: compute-optimal training uses about 20 tokens per parameter; it minimises training compute only, so models that will serve heavy traffic are trained on far more tokens. (Ch 13)
- **Chunking**: splitting documents into retrievable passages for RAG. (Ch 31)
- **CISPO**: an RL objective that clips the importance weight but keeps every token's gradient, so rare high-ratio tokens still learn. (Ch 19)
- **CLIP**: image and text encoders trained contrastively into a shared embedding space. (Ch 14)
- **Clip-higher**: asymmetric PPO/GRPO clipping with a larger upper bound so rare useful tokens can grow; part of DAPO. (Ch 19)
- **Cold start**: no history for a new user or item. (Ch 43)
- **Concept drift / covariate shift / prior shift**: the input–label relation / the input distribution / the label base rate changes. (Ch 47)
- **Conformal prediction**: wrapping any model so its prediction intervals or sets reach a chosen coverage, using quantiles of held-out residuals. (Ch 45)
- **Constitutional AI**: training harmlessness from AI feedback against a written set of principles: self-critique and revision, then AI-labelled preferences. (Ch 27, 18)
- **Constrained decoding**: masking logits so output follows a grammar or schema. (Ch 21)
- **Contamination**: evaluation items (or close paraphrases) present in training data, inflating scores. (Ch 16, 23)
- **Context parallelism**: splitting each sequence across GPUs, with key–value blocks passed round a ring for attention. (Ch 17)
- **Context window**: maximum number of tokens a model can attend to at once. (Ch 10, 22)
- **Continuous batching**: adding and removing requests from the running batch at each decode step. (Ch 21)
- **Contrastive loss (InfoNCE)**: pull matching pairs together and push in-batch negatives apart. (Ch 29, 14)
- **Critical batch size**: the batch size beyond which larger batches stop reducing the number of training steps much; about the gradient noise scale. (Ch 7)
- **CUPED**: variance reduction for experiments using a pre-experiment covariate. (Ch 2)

## D–H

- **DAPO**: a GRPO variant with clip-higher, dynamic sampling, token-level loss and overlong shaping. (Ch 19)
- **Data contract**: agreed schema, semantics, freshness and ownership for a dataset. (Ch 48)
- **Data leakage**: information unavailable at prediction time used in training. (Ch 3, 48)
- **DCG / NDCG**: ranking metric with logarithmic position discount, normalised by the ideal ranking. (Ch 44, 4)
- **Decoder-only model**: transformer with a causal mask trained on next-token prediction (GPT, Llama). (Ch 10, 12)
- **Diffusion language model**: a model that generates by iteratively unmasking tokens in parallel rather than left to right. (Ch 11)
- **Distillation**: training a small student to imitate a larger teacher. (Ch 15, 19)
- **Double descent**: test error that falls, rises near the interpolation threshold, then falls again as model size or training grows. (Ch 3)
- **DPO**: direct preference optimisation, learning from preference pairs without a reward model or RL. (Ch 18)
- **Dr. GRPO**: GRPO without per-response length normalisation and standard-deviation scaling, removing their biases. (Ch 19)
- **Dropout**: randomly zeroing activations during training to regularise. (Ch 5)
- **ECE (expected calibration error)**: the bin-weighted average gap between predicted confidence and observed accuracy. (Ch 4)
- **Edge of stability**: the regime where gradient descent keeps the loss sharpness near 2/η while the loss still falls. (Ch 7)
- **Elo rating**: a Bradley–Terry skill score fitted from pairwise wins; 400/ln 10 Elo points per unit of logit. (Ch 23)
- **Embedding**: dense vector representing an item, word or text so that similar things are close. (Ch 29, 8)
- **Encoder-only model**: bidirectional transformer trained with masked language modelling (BERT). (Ch 12)
- **Entropy collapse**: the policy's token entropy falling fast during RL so it stops exploring; countered by clip-higher, entropy bonuses or temperature. (Ch 19)
- **Erlang C**: the queueing formula for the probability that an arrival waits, used to staff agents or servers for a target wait time. (Ch 45)
- **Expert parallelism**: placing MoE experts on different GPUs, with all-to-all communication to route tokens. (Ch 17)
- **Exposure bias**: training on true previous tokens but generating from one's own. (Ch 8)
- **F1 score**: harmonic mean of precision and recall. (Ch 4)
- **Faithfulness / groundedness**: generated claims are supported by the provided context. (Ch 25, 24)
- **Feature store**: system serving consistent features offline (training) and online (serving). (Ch 47)
- **Few-shot prompting**: including examples in the prompt. (Ch 22)
- **Fine-tuning**: continuing training of a pre-trained model on task data. (Ch 20, 41)
- **FlashAttention**: exact attention computed in tiles to avoid materialising the full matrix; faster and memory-efficient. (Ch 10)
- **FP8**: 8-bit floating point (e4m3, e5m2) used for faster training and inference with fine-grained scaling. (Ch 7, 17, 21)
- **FSDP**: fully sharded data parallelism: weights, gradients and optimiser states sharded across data-parallel ranks (ZeRO-3). (Ch 17)
- **GAE**: generalised advantage estimation: a λ-weighted mix of multi-step advantage estimates used in PPO. (Ch 18)
- **Gated DeltaNet**: a linear-attention layer with a delta-rule update and a forget gate, used in hybrid models. (Ch 11)
- **GBDT**: gradient-boosted decision trees (XGBoost, LightGBM, CatBoost). (Ch 40)
- **GQA (grouped-query attention)**: several query heads share one key-value head, shrinking the KV cache. (Ch 10, 21)
- **Gradient clipping**: capping gradient norm to avoid exploding updates. (Ch 7, 5)
- **Grokking**: delayed generalisation: a network fits the training set early, then generalises suddenly much later, typically with weight decay on small algorithmic tasks. (Ch 3)
- **GRPO**: group relative policy optimisation: PPO-style clipped updates with advantages computed from the rewards of a group of responses to the same prompt, so no value model is needed. (Ch 19)
- **GSPO**: group sequence policy optimisation: one length-normalised sequence-level importance ratio, clipped per response instead of per token. (Ch 19)
- **Guardrail metric**: metric that must not get worse in an experiment. (Ch 2)
- **Hallucination**: fluent output not supported by input or facts. (Ch 28, 31)
- **HNSW**: graph-based ANN index with layered navigable small-world graphs. (Ch 30)
- **Hybrid search**: combining lexical (BM25) and dense retrieval, often with reciprocal rank fusion. (Ch 30)

## I–M

- **Importance sampling**: estimating an expectation under one distribution from samples of another by weighting each sample by the probability ratio. (Ch 18, 19)
- **In-context learning**: model adapts to a task from examples in its prompt without weight updates. (Ch 22)
- **Induction head**: an attention head that finds a previous occurrence of the current token and copies the token after it. (Ch 26)
- **Interleaving**: comparing two rankers by mixing their results in one list. (Ch 44, 2)
- **IPO**: a DPO variant with a squared loss towards a fixed margin, so deterministic preferences do not push log-ratios to infinity. (Ch 18)
- **IPS (inverse propensity scoring)**: reweighting logged outcomes by 1/(probability the old system showed the item) to remove exposure or position bias. (Ch 43, 44)
- **IRT (item response theory)**: modelling item difficulty and model ability to choose informative test items and compare models. (Ch 23)
- **IsoFLOP curve**: loss against model size at a fixed compute budget, used to locate the compute-optimal size. (Ch 13)
- **Item2vec**: word2vec applied to sessions or baskets to embed items. (Ch 8)
- **Jailbreak**: an input crafted to make a model ignore its safety training. (Ch 27, 28)
- **Kappa (Cohen's)**: inter-annotator agreement corrected for chance. (Ch 48)
- **KL divergence**: how one distribution differs from another; used as a penalty in RLHF and in distillation. (Ch 1, 18)
- **KL penalty**: a β-weighted KL divergence to the reference model in the RL objective or loss, keeping the policy close to where the reward is trustworthy. (Ch 18, 19)
- **KTO**: preference alignment from unpaired thumbs-up/down labels. (Ch 18)
- **KV cache**: stored keys and values of past tokens to avoid recomputation during generation. (Ch 21)
- **Label smoothing**: training against a target that puts 1 − ε on the true class and spreads ε over the rest, curbing over-confidence. (Ch 5, 4)
- **LambdaMART**: GBDT-based learning-to-rank that optimises NDCG-weighted pairwise gradients. (Ch 44)
- **Learning to rank (pointwise / pairwise / listwise)**: losses on single items / pairs / whole lists. (Ch 44)
- **Likelihood displacement**: in DPO, chosen and rejected log-probabilities both falling while their gap grows. (Ch 18)
- **Linear attention**: attention with a kernel feature map so it can be computed as a recurrence with a fixed-size state. (Ch 11)
- **Linear probe**: a linear classifier trained on frozen activations to test whether a property is linearly decodable; it shows presence, not use. (Ch 26)
- **Little's law**: in a stable system, items in flight = arrival rate × time in the system; sizes concurrency for servers and GPUs. (Ch 42)
- **LLM-as-judge**: using an LLM to score or compare outputs, checked against human labels. (Ch 24)
- **Logit**: unnormalised score before softmax or sigmoid. (Ch 5)
- **Logit lens**: decoding intermediate residual-stream states with the output head to see predictions form across layers. (Ch 26)
- **LoRA / QLoRA**: training low-rank update matrices instead of full weights / doing so on a 4-bit quantised base. (Ch 20)
- **Mamba**: a selective state-space model whose transitions depend on the input; linear time in sequence length. (Ch 11)
- **MAP / MRR**: mean average precision / mean reciprocal rank of the first relevant result. (Ch 4, 30)
- **Masked language modelling**: predicting hidden tokens from both sides. (Ch 12)
- **McNemar's test**: a paired test for two classifiers on the same items that uses only the items where they disagree. (Ch 2, 24)
- **MCP (Model Context Protocol)**: open protocol connecting LLM apps to tools and data sources. (Ch 33)
- **MDE**: minimum detectable effect for a given sample size and power. (Ch 2)
- **MFU (model FLOPs utilisation)**: model FLOPs achieved per second divided by the hardware's peak. (Ch 17)
- **Mid-training**: a phase between pretraining and post-training with a targeted mixture (long context, reasoning, high-quality data). (Ch 16)
- **MinHash**: hashing that estimates Jaccard similarity of documents; with LSH it finds near-duplicates at scale. (Ch 16)
- **Mixed precision**: computing in bf16/fp16 while keeping fp32 master weights. (Ch 6)
- **MLA (multi-head latent attention)**: attention that caches a small latent per token instead of full keys and values. (Ch 11)
- **Model merging**: combining fine-tuned models of the same base in weight space (averaging, task arithmetic, TIES, DARE). (Ch 20)
- **MoE (mixture of experts)**: a router sends each token to a few of many expert networks: total parameters grow while compute per token tracks only the active ones. (Ch 11)
- **MQA (multi-query attention)**: all query heads share a single key-value head: the smallest KV cache, at some quality cost; GQA is the middle ground. (Ch 10)
- **Multi-token prediction**: predicting several future tokens per position, for training signal and speculative decoding. (Ch 11)
- **Muon**: an optimiser that orthogonalises each hidden matrix's momentum update with Newton–Schulz iterations. (Ch 7)
- **µP (maximal update parametrisation)**: width-dependent initialisation and learning rates that let hyperparameters transfer from small to large models. (Ch 7)

## N–R

- **Negative sampling**: training with a few random negatives instead of a full softmax. (Ch 8)
- **Newsvendor rule**: stock the demand quantile cost_under / (cost_under + cost_over), the optimum when leftovers and shortages have different costs. (Ch 45)
- **Novelty effect**: temporary change in behaviour because something is new. (Ch 2)
- **Nucleus (top-p) sampling**: sample from the smallest token set with cumulative probability ≥ p. (Ch 21)
- **On-policy distillation**: the student generates, the teacher scores every token (reverse KL): on-policy data with a dense signal. (Ch 19)
- **Overfitting**: fitting noise in training data so test performance suffers. (Ch 3)
- **p-value**: probability of data at least as extreme as observed if the null hypothesis were true. (Ch 2)
- **PagedAttention**: KV cache stored in fixed-size blocks to reduce memory waste (vLLM). (Ch 21)
- **pass^k**: the probability that all of k attempts succeed; a reliability measure for agents. (Ch 25, 23)
- **pass@k**: the probability that at least one of k samples is correct, estimated without bias as 1 − C(n−c, k)/C(n, k) from n samples with c correct. (Ch 19, 25)
- **PEFT**: parameter-efficient fine-tuning (LoRA, adapters, prefix and prompt tuning). (Ch 20)
- **Performance gap recovered (PGR)**: in weak-to-strong experiments, the fraction of the gap between weak supervisor and strong ceiling that the student recovers. (Ch 27)
- **Perplexity**: exp of average negative log-likelihood per token. (Ch 23, 1)
- **Pinball (quantile) loss**: asymmetric loss whose minimiser is the q-th quantile: q(y − ŷ) when under-predicting, (1 − q)(ŷ − y) when over. (Ch 4, 45)
- **Pipeline bubble**: idle time in pipeline parallelism at the start and end of each batch, (p − 1)/(m + p − 1). (Ch 17)
- **Point-in-time join**: joining each label to feature values as they were at prediction time. (Ch 48)
- **Positional encoding**: injecting token order (sinusoidal, learned, RoPE, ALiBi). (Ch 10)
- **PPO**: proximal policy optimisation: policy-gradient updates on a clipped probability ratio so each batch cannot move the policy too far. (Ch 18)
- **Precision / recall**: share of predicted positives that are right / share of actual positives found. (Ch 4)
- **Prefill / decode**: processing the prompt in parallel / generating one token per step. (Ch 21)
- **Prefix (prompt) caching**: reusing the KV cache of a shared prompt prefix across requests, cutting prefill cost and time to first token. (Ch 21, 22)
- **Process reward model (PRM)**: a model that scores each step of a reasoning chain rather than only the final answer. (Ch 19)
- **Prompt injection**: instructions hidden in content the model reads, which it then follows. (Ch 28, 22)
- **PSI**: population stability index, a drift score between two distributions. (Ch 47)
- **QK-norm**: normalising queries and keys before attention to keep attention logits bounded. (Ch 7)
- **Quantisation**: storing weights or activations in fewer bits. (Ch 21)
- **RAG**: retrieval-augmented generation, grounding the model in retrieved documents. (Ch 31)
- **ReAct**: agent pattern interleaving reasoning and actions. (Ch 33)
- **Reciprocal rank fusion (RRF)**: combine rankings by summing 1/(k + rank). (Ch 30)
- **Red-teaming**: deliberately attacking a model or system to find failures before users or adversaries do. (Ch 27, 28)
- **Regularisation**: techniques to reduce overfitting (L1, L2, dropout, early stopping). (Ch 3)
- **REINFORCE**: the score-function policy gradient E[R ∇log π(y)], usually with a baseline subtracted to cut variance. (Ch 18)
- **Reranker**: a slower, more accurate model re-ordering the top candidates. (Ch 30, 44)
- **Residual connection**: adding a layer's input to its output, easing gradient flow. (Ch 10, 5)
- **Reward hacking**: optimising a proxy reward in ways that do not reflect true quality. (Ch 27, 18)
- **Reward model**: a model, usually the LLM with a scalar head, trained on preference pairs to score responses for RL or best-of-n. (Ch 18)
- **RLAIF**: RL from AI feedback: preference labels produced by a model, often guided by written principles, instead of people. (Ch 15, 18)
- **RLHF**: reinforcement learning from human feedback: a reward model trained on preference pairs, then RL (classically PPO) against it with a KL penalty to the reference model. (Ch 18)
- **RLOO**: REINFORCE with a leave-one-out baseline: each sample's baseline is the mean reward of the other samples for the same prompt. (Ch 18, 19)
- **RLVR**: reinforcement learning with verifiable rewards: programmatic checks of answers, tests or end states as the reward. (Ch 19)
- **RMSNorm**: layer normalisation without mean-centring or bias: x / RMS(x) times a learned gain; cheaper and standard in modern LLMs. (Ch 10)
- **RoPE**: rotary position embeddings, rotating query and key vectors by position. (Ch 10)

## S–Z

- **Scaled dot-product attention**: softmax(QKᵀ/√d)V. (Ch 10)
- **Self-consistency**: sample several reasoning paths and take a majority vote. (Ch 19, 22)
- **Sentence transformer**: encoder fine-tuned so pooled embeddings reflect sentence similarity. (Ch 29, 12)
- **SFT**: supervised fine-tuning on prompt–response pairs. (Ch 18)
- **Shadow deployment**: new model receives copied traffic; outputs logged, not used. (Ch 47)
- **SHAP**: feature attributions based on Shapley values. (Ch 40)
- **SigLIP**: CLIP-style image–text pretraining with a per-pair sigmoid loss instead of a batch softmax. (Ch 14)
- **SimPO / ORPO**: reference-free preference losses: SimPO uses length-normalised log-probability with a target margin; ORPO adds an odds-ratio term to the SFT loss. (Ch 18)
- **Softmax / sigmoid**: turn logits into a distribution over classes / a probability for one class. (Ch 1, 5)
- **Sparse autoencoder (SAE)**: an over-complete autoencoder with sparse latents used to find interpretable features in activations. (Ch 26)
- **Speculative decoding**: a draft model proposes tokens that the large model verifies in one pass. (Ch 21)
- **SRM (sample ratio mismatch)**: observed traffic split differs from the design, signalling a bug. (Ch 2)
- **Steering vector**: a direction added to the residual stream to change a model's behaviour. (Ch 26)
- **Structured output**: model output constrained to a JSON schema. (Ch 22, 21)
- **Superposition**: representing more sparse features than dimensions as overlapping directions. (Ch 26)
- **SwiGLU**: a gated feed-forward block, (SiLU(xW₁) ⊙ xW₃)W₂, with hidden width about 8/3 of d_model to match a 4× MLP's parameters. (Ch 10)
- **Switchback test**: an experiment that alternates whole regions between treatment and control over time slots, for systems where units interfere. (Ch 2, 45)
- **Sycophancy**: telling users what they want to hear, such as abandoning correct answers under pushback. (Ch 27)
- **Teacher forcing**: feeding true previous tokens during training. (Ch 8)
- **Temperature**: divides logits before softmax; lower is more deterministic. (Ch 21)
- **Tensor parallelism**: splitting each matrix multiplication across GPUs within a node. (Ch 17)
- **Test-time compute**: spending more inference tokens (reasoning, sampling) to improve accuracy. (Ch 13, 19)
- **Tokeniser**: maps text to integer ids from a fixed vocabulary. (Ch 9)
- **Tool calling (function calling)**: model outputs a structured call that the application executes. (Ch 33)
- **Top-k / min-p sampling**: sample only from the k most likely tokens / from tokens with probability at least p times the top token's. (Ch 21)
- **Training–serving skew**: features computed differently in training and production. (Ch 47)
- **Transcoder**: a sparse replacement for an MLP layer trained to map its input to its output through interpretable latents; used for circuit tracing. (Ch 26)
- **TTFT / TPOT**: time to first token (queueing plus prefill) / time per output token (one decode step); latency ≈ TTFT + output tokens × TPOT. (Ch 21)
- **Two-tower model**: separate user and item encoders producing embeddings for fast retrieval. (Ch 43)
- **Uplift modelling**: predicting the effect of a treatment on each individual. (Ch 2, 45)
- **Value model (critic)**: a network that predicts expected future reward from a state, used as PPO's baseline and for GAE. (Ch 18)
- **Vanishing / exploding gradients**: gradients shrinking or growing exponentially through depth or time. (Ch 5, 8)
- **Vector database**: storage and ANN search over embeddings with metadata filters. (Ch 30)
- **ViT (vision transformer)**: a transformer over image patches embedded as tokens. (Ch 14)
- **VLM**: vision-language model, an LLM that takes images as input. (Ch 14)
- **WAPE**: weighted absolute percentage error, Σ|y − ŷ| / Σ|y|; stable when many actuals are zero. (Ch 4, 45)
- **Weak-to-strong generalisation**: training a strong model on a weak supervisor's labels; an analogy for supervising superhuman models. (Ch 27)
- **Weight decay**: penalty pulling weights towards zero. (Ch 7, 3)
- **Word2vec**: shallow model learning word embeddings from context prediction. (Ch 8)
- **WSD schedule**: warmup–stable–decay learning-rate schedule: constant rate for most of training, then a short decay. (Ch 7)
- **YaRN**: a RoPE context-extension method that interpolates only low-frequency dimensions. (Ch 10)
- **z-loss**: a penalty on the log of the softmax normaliser that keeps output logits from drifting. (Ch 7)
- **ZeRO**: sharding optimiser states (stage 1), gradients (2) and weights (3) across data-parallel ranks. (Ch 17)
- **Zero-shot**: performing a task with instructions only, no examples. (Ch 22)
